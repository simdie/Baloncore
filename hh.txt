0:48

The “one-off next strong step” method is like pair-building live: we look at the current state, choose the most valuable next move, implement it, test it, then reassess. It is flexible and fast. That’s why Stage 1 grew well: we kept adapting to what the code needed next.

The operator manual is different: it gives BALONCORE a repeatable build doctrine. It captures the bigger strategy, rules, quality bar, safety constraints, acceptance criteria, and verification steps for each stage before we start coding.

So the difference is:

One-off next steps answer: “What should we build next right now?”
Operator manual answers: “How should BALONCORE be built consistently across all stages?”
The one-off method is good for momentum. The manual is good for scale, consistency, and not losing the vision.

For Stage 1, the live next-step style worked because we were discovering the shape of the engine. But from Stage 2 onward, the system gets bigger: evidence database, dashboard, agents, cloud, Web3, autonomous mode, SaaS. Without an operator manual, we risk building powerful pieces that don’t align. With it, every future step can be checked against the stage mission, acceptance criteria, and safety rules.

Best path is to use both:

Use Baloncore_prompts.md as the strategy and quality bar.
Continue using “next strong step” as the execution rhythm.
That means we stay fast, but we don’t drift.
